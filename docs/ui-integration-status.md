## 경기의 데이터 흐름

1. 경기 주차로 진행하면 준비 화면을 엽니다. 취소하면 주차와 결과를 진행하지 않습니다.
2. 실제 선수단과 출전 순서·권고를 경기 API로 전달합니다.
3. 계산 결과의 로그를 관전 화면에서 재생합니다. 화면이 별도로 명중·피해를 결정하지 않습니다.
4. 결과 확인 시 우리 경기 결과를 주차 진행에 반영하고 보고서·경력을 저장합니다.

준비 상태와 완료 결과를 저장하며 새로고침 시 복구하는 처리가 있습니다. 계산 중 새로고침하면 준비부터 재시도합니다. API 실패를 간이 승패로 대체하지 않습니다. 다중 탭·선수단 변경·저장 실패까지 포함한 결과 반영 보호는 추가 작업입니다.

## 관전·인계에서 보존한 처리

- 교체로 엔진의 포켓몬 배열 순서가 바뀌어도 원래 객체에서 종료 상태를 읽습니다.
- 같은 종 여러 마리의 경기 내부 이름을 구분하고 화면에는 원래 이름을 표시합니다.
- 엔진의 현재 타입·기술 슬롯·실제 PP를 기록으로 받습니다. 프레셔 소모와 변신 후 슬롯을 단순 사용 횟수로 추정하지 않습니다.
- 상성 배율은 현재 상대 타입을 기준으로 한 기본 상성입니다. 특성·도구까지 포함한 최종 피해 예측은 아닙니다.
- 보고서는 직접 피해·격파와 독·날씨 등 간접 피해를 구분합니다.
- 기술 한국어 사전은 화면과 중계에 함께 사용합니다. 사전에 있는 CAP 창작 기술명이 리그 사용 허용을 뜻하지는 않습니다.

## 로컬·배포 차이

[로컬 서버](../scripts/serve.mjs)는 경기 API만 연결하고 상대 분석·기술 연구 API는 연결하지 않습니다. 웹 기능 전체를 로컬에서 확인하려면 이 라우팅을 먼저 맞춰야 합니다.

Vercel에는 세 API 파일이 있지만 파일 존재와 실제 배포 성공·응답 확인은 구분합니다. 이번 문서 정리에서는 배포 상태를 새로 확인하지 않았습니다.
