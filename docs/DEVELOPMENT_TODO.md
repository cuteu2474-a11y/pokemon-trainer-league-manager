### 이번 구현 범위 · 2026-10-27

- 이적시장: 후보 목록 통합, 검색·리그 필터·페이지 이동, 집계 구분, 공통 제안액 계산, 정밀 조사, 6능력치 성장 여유 평가.
- 주간 진행: 기본 훈련·회복 방침 저장, 기술 연구 응답 대기, 기존 주간 처리 재사용, 시장 마감·경기 준비·이적 제안·포획 후보·공석에서 중단, 기간 요약. 시즌 정산·신인 배출·새 시즌은 수동 확인합니다.
- 경기 피드백: 경기 ID별 미팅·출전 순서 저장, 결과 전 임시 요약과 반영 후 확정 변화 구분, 실전 교체·상대 기절 장면 재생, 미출전 선수 제외.
- 메뉴: 홈·선수단·리그·영입·구단으로 묶고 하위 화면은 각 메뉴에 유지. 반복 육성 패널은 선수단에 모았습니다.
- 훈련: 자율·주간·AI 구단 훈련을 능력치별 CA·PA 상한에 연결. 로컬 서버의 상대 분석·기술 연구 API도 연결했습니다.

미완료: 탐색 결과를 포함한 통합 기간 요약, 화면 이동 이력·뒤로 가기, 권고별 실행 장면의 정밀 대응, 실제 브라우저에서의 다중 탭 검증. 기존 경기 전 컨디션 표시도 별도 작업입니다.

검증: 시장·주간 진행·경기 성장·선플 관련 29개 검사, 웹 스크립트 검사 통과. 로컬 세 API의 JSON 응답도 확인했습니다. 브라우저 실행 파일을 설치하지 못해 화면 통합 검증은 수행하지 못했습니다. 새 게임부터 두 번째 경기, 전체 시즌·다년 운영은 미확인입니다.

### 계약·급여·재정 추가 구현 · 2026-10-27

- 영입 시 시즌 연봉·계약 기간을 선택하고 이적료·계약금·연봉 총액 상한·이번 시즌말 자금 전망을 표시합니다.
- 주전·후보·아카데미에 고유 계약 ID를 부여하고 매주 급여를 지급합니다. 계약 종료·이적 이후에는 이전 구단에 다시 청구하지 않습니다.
- 재계약은 연봉과 연장 기간을 선택합니다. 만료 4주 전에는 자동 진행을 멈추고 재계약 또는 만료 후 퇴단을 결정합니다. 실제 만료 후에는 포켓몬을 그대로 데리고 자유계약 시장으로 이동합니다.
- 필수 급여 부족분은 미지급금으로 기록하고, 경기 보상·매각·지원금 수입의 50%로 상환합니다. 미지급금이 있으면 유료 선택 지출을 제한합니다.
- 구단의 재정·계약 화면에서 잔액·미지급금·예정 급여·정산 내역·시즌별 재정 기록을 확인합니다. 선수단 변경과 비용은 한 거래로 반영하며, 오류가 나면 함께 복구합니다.
- 기존 저장은 도입 주차부터 지급합니다. 연봉의 구화폐 변환에는 버전을 남겨 반복 증액을 막습니다. 경기 보상·지원금·AI 이적·운영비도 재정 장부에 연결했습니다.

검증: 계약·재정, 시장, 빠른 진행, 탐색 관련 검사 38개 및 웹 스크립트·새 모듈 문법 검사 통과. 브라우저 화면과 새 게임부터 두 번째 경기까지의 실제 조작, 다년간 구단 운영은 이번 검사 범위가 아닙니다. 성적·육성·재정의 종합 시즌 평가는 아직 남아 있으며 현재는 재정 항목만 기록합니다.

### 출전 확정·결과 저장 보호 추가 구현 · 2026-10-27

- 출전 확정 전에 기술 연구를 마치고, 양 구단 선수단·기술·능력치·권고·출전 순서·난수 시드를 경기용 사본으로 저장합니다.
- 사본에는 경기 ID, SHA-256 입력 식별값, 규정·엔진 버전을 붙입니다. API와 브라우저가 같은 입력인지 확인하며, 이전 요청·다른 경기의 응답은 거절합니다.
- 확정 후에는 등록된 선수단의 편성·이적·방출·유료 육성·포획 등록과 뒤늦은 기술 연구 적용을 막습니다. 계산 실패·새로고침 후에도 같은 사본과 시드로 재시도합니다. 편성을 바꾸려면 확정을 해제합니다.
- 포켓몬에 고유 ID와 소유 트레이너 ID를 붙이고 경기 등록 시 검사합니다. 기존 저장의 ID는 한 번 부여하며 이적 후에도 유지합니다.
- 경기 정산은 Web Locks와 저장본 버전 확인으로 직렬 처리합니다. 순위·경기 수입·성장·기록·급여 정산을 반영한 뒤 저장에 성공한 경우에만 완료 처리합니다. 저장 실패 시 변경 전 상태로 복구합니다.
- 같은 경기의 반영 기록은 저장에 남겨 두 번 지급하지 않습니다. 다른 탭의 진행이 감지되면 저장 불러오기를 제공합니다. 지난 경기에는 확정 입력과 계산 결과를 함께 남깁니다.

검증: 저장 사본·소유권·입력 변경 거절·두 탭의 동시 정산·저장 실패 복구·실제 Showdown 경기 및 기존 재정·진행·탐색 검사 36개 통과. 실제 브라우저 여러 탭과 모바일 화면 조작, 다년 플레이는 미확인입니다. 결과 반영에는 Web Locks를 지원하는 브라우저가 필요합니다. 서버 계정 저장이나 여러 기기 간 동기화는 포함하지 않습니다.

## 1. 우선 수정

### 이적시장 통합

- [x] 새 스카우팅 화면과 기존 영입 화면을 하나의 후보 목록·상세·협상 화면으로 통합
- [x] 후보 선정·가격·평가·협상에 공통 데이터를 사용하고 기존 중복 표시 제거
- [x] 후보 수를 전체 등록·검색 결과·현재 협상 가능으로 구분
- [x] 기본 평가액과 제안 배율을 적용한 실제 제안액을 구분해 표시
- [x] 목록·상세·확인창·실제 차감액에 동일한 제안액 사용
- [x] 시장 평가의 이전 종합 CA/PA 참조를 능력치별 statCA/statPA로 변경
- [x] 트레이너 잠재력과 동반 포켓몬의 성장 여유를 다른 항목으로 표시
- [x] 조사하지 않은 정보는 추정 범위로 표시하고 정밀 조사 후 확인한 값과 구분

**화면:** 후보 목록에서 선수를 선택하면 우리 주전과 비교하고, 동반 포켓몬·전술 성향·성장 여유를 확인한 뒤 같은 화면에서 협상합니다. 협상에는 평가액·제안액·요구 연봉·계약 기간·영입 후 잔액을 표시합니다.

**완료 기준:** 같은 후보의 가격과 후보 수가 화면마다 이유 없이 달라지지 않습니다. 높은 PA 개체의 성장 여유가 구형 필드 누락으로 0에 가깝게 계산되지 않으며, 표시한 금액과 실제 지출이 일치합니다.

### 개막전까지 빠른 진행과 주간 활동 간소화

- [ ] 구단 선택 후 직접 준비와 추천 계획으로 개막전까지 진행 중 선택
- [ ] 감독실에 다음 주와 다음 중요 일정까지 진행 제공
- [x] 매주 같은 활동을 다시 고르지 않도록 기본 훈련·회복 방침 저장
- [ ] 자동 진행에서도 각 주의 훈련·급여·탐색·계약·AI 구단 활동을 정상 정산
- [x] 주간 비동기 기술 연구를 정산하거나 저장 가능한 대기 상태로 처리한 뒤 다음 주 진행
- [x] 경기 준비·응답이 필요한 이적 제안·계약 결정·출전 공석·미처리 포획 후보에서 자동 진행 중단
- [x] 이적시장 마감처럼 마지막 결정 기회가 사라지는 일정은 지나가기 전에 중단
- [ ] 중단 후 다시 진행하거나 새로고침해도 정산·훈련이 중복되지 않도록 처리
- [ ] 진행한 기간의 훈련·수입·지출·탐색 결과를 한 번에 요약
- [ ] 능력치가 오르기 전에도 경험 진척과 실제 활동 내용을 표시

**흐름:** 추천 준비 계획 확인 → 자동 주간 처리 → 중요 사건이 생기면 중단 → 사건 처리 또는 개막전 준비 화면 진입입니다. 권고·훈련 방침은 언제든 바꿀 수 있습니다. 자동 진행이 지출이 큰 신규 계약·영입·방출을 임의 승인하지 않습니다.

**완료 기준:** 일정만 건너뛰지 않고 수동으로 같은 계획을 진행한 경우와 정산 결과가 일치합니다. 자동 진행이 경기 준비를 통과하거나 중요한 결정을 누락하지 않으며, 첫 경기를 보기 위해 매주 같은 버튼을 반복해서 누를 필요가 없습니다.

### 경기 전후 피드백 연결

- [x] 경기 전 권고·수용 여부·출전 순서를 해당 경기 ID에 저장
- [ ] 경기 종료 첫 화면에 결정적 장면·권고 실행·실제 성장 변화를 우선 표시
- [x] 권고 수용, 실제 행동, 행동 이후 결과를 각각 구분
- [ ] 실전 기록에 있는 교체·격파·생존·PP 보존 장면을 관련 권고와 연결
- [x] 해당 장면 보기 버튼으로 관련 주자 대결과 턴을 재생 (교체·상대 기절 기록 기준)
- [x] 감독 신뢰·행동 성향·능력 경험치의 실제 이전값과 이후값 표시
- [x] 경기 확인 전에는 임시 요약, 결과 반영 후에는 확정 성장 기록을 사용해 중복 지급 방지
- [ ] 실행 기회가 없거나 효과를 확인할 수 없으면 그 사유를 표시
- [x] 미출전 주자에게 경기 활약과 경험을 만들어 붙이지 않음
- [x] 자세한 전투·훈련 보고서는 요약 아래에서 선택해서 열도록 정리

**표현 기준:** 권고와 일치하는 교체 후 유리한 대면을 확보했다면 그 장면과 실제 변화를 보여줍니다. 비교 경기 없이 “권고 덕분에 승리했다”거나 승률이 특정 수치만큼 올랐다고 단정하지 않습니다. 예시 숫자를 실제 성장량처럼 표시하지 않습니다.

**완료 기준:** 경기 후 무엇이 바뀌었고 어떤 장면에서 그 변화가 발생했는지 확인할 수 있습니다. 첫 경기의 피드백을 확인한 뒤 다음 경기에서 다른 권고·편성·출전 순서를 선택할 수 있습니다.

#### 출전 선수단 확정과 결과 반영 보호

##### 화면과 흐름

경기 준비 → 출전 순서·포켓몬 확인 → 출전 확정 → 경기 계산 → 관전 → 결과 반영 순서로 진행합니다.

- 확정 전에는 편성을 바꿀 수 있습니다. 선수단이 변경되면 준비 화면도 갱신하고 출전 자격을 다시 확인합니다.
- 확정 후 계산·관전·결과 반영이 끝날 때까지 해당 경기에 등록된 트레이너의 이적·방출·포켓몬 편성·세트 변경을 막습니다. 버튼 옆에 “경기 결과 확인 후 변경할 수 있습니다”라고 표시합니다.
- 확정 직전에 진행 중이던 기술 연구 등 비동기 응답도 등록된 세트를 뒤늦게 바꾸지 못하게 합니다. 해당 작업을 먼저 정산하거나 경기 종료 후 적용할 대상으로 보관합니다.
- 이 제한은 우리 구단뿐 아니라 해당 경기의 상대 구단에도 적용합니다.
- 계산 실패 시 같은 확정 선수단으로 재시도할 수 있습니다. 편성을 바꾸려면 확정을 해제하고 준비 화면으로 돌아갑니다.
- 관전을 건너뛰어도 같은 경기 결과를 적용합니다. 새로고침을 이유로 선수단이나 난수 시드를 새로 뽑지 않습니다.

##### 저장과 검증

출전 확정 시 현재 선수단과 별도로 경기용 사본을 저장합니다.

| 저장 항목 | 내용 |
| --- | --- |
| 경기 식별 | 시즌, 라운드, 양 구단 ID, 경기 ID |
| 출전 정보 | 트레이너 ID와 출전 순서, 포켓몬 ID와 포획자 |
| 전투 입력 | 종·폼, 개별 CA/PA, 성격, 기술·PP 기준, 특성, 도구, 적용할 컨디션 |
| 계산 기준 | 난수 시드, 대회 규정 버전, 전투 엔진 버전, AI 전술·판단에 필요한 설정 |
| 진행 상태 | 준비·확정·계산·관전·반영 완료, 선수단 변경 버전 |

경기 API는 확정한 사본으로 계산합니다. 결과에는 경기 ID와 입력을 식별할 값을 포함합니다. 브라우저는 현재 대기 중인 경기와 일치하는 결과만 받습니다.

결과 확인 시에는 다음을 확인한 뒤 순위·수입·경험·기록을 함께 반영합니다.

- 현재 시즌·라운드가 해당 경기와 일치하는지
- 선수단이 확정 후 변경되지 않았는지
- 같은 경기 결과가 이미 반영되지 않았는지

일치하지 않으면 일부 보상만 지급하지 않고 반영을 중단합니다. 저장을 복원했거나 다른 탭에서 선행 진행한 경우에도 같은 검사를 사용합니다. 저장 자체가 실패하면 완료로 표시하지 않고 재시도할 수 있게 합니다.

현재 웹은 우리 구단 경기만 실제 전투로 계산하며, 나머지 19경기는 간이 계산을 사용합니다.

검증: 순위·일정·실제 연승전 어댑터·저장 정산·급여·주간 진행 관련 검사 31개 통과. 새 순위 검사 9개는 다자 동률 비재귀 처리, 양방향 상대 전적, 중복 전적 제외, 추첨 이관·복원, 웹/리그 동일 순위, 실제 웹 시즌 전환 함수의 12개 승강 자리, 간이 점수, 순위표 모듈과 저장 가드 연결을 확인했습니다. 360경기 일정 검사는 간이 결과 기반이며, 모바일 직접 조작과 실제 전투 시즌 완주를 뜻하지 않습니다.


### 대회 예외 규정

#### 적용할 규정

턴 제한·무승부·상태 인계·주자별 단체전 통합 강화권·전문 타입 편성 보너스를 아래 기준으로 연결했습니다. 세부 기준과 결정 이유는 4-1~4-4에 있습니다.

현재 구현 규정 버전은 `relay-specialty-v4-20261027`입니다. 실제 전투와 AI 가상 전투가 같은 턴 제한·강화권·전문 편성·폼 능력치 처리를 사용합니다. 기존 완료 기록은 변경하지 않으며, 이전 규정으로 확정했지만 아직 끝내지 않은 경기는 출전 준비부터 다시 확인합니다.

이번 구현: 300턴 완료 후 양쪽 탈락, 종료 사유 저장, 엔진의 `|tie` 로그 처리, 생존 수 초기화 오류 수정, 현재 도구·도구 소모 이력·수면 진행·소모된 보호 형태의 인계, 대회 규정과 인계 상태 표시. 원래 기술 슬롯의 PP를 유지하며 전장·일시 효과를 이전 전투 객체째 복사하지 않습니다.

검증: 이번 전문 편성 변경은 기존 전투·강화·등록·상대 분석 검사를 포함해 관련 검사 58개가 통과했습니다. 전문 편성 전용 7개는 6마리 공통 타입, 성격 후 내림, HP·스피드·CA/PA 보존, 메가 폼 재계산, 변신·교체·AI 복제, 테라·기절 후 자격 유지, 고정 피해, 실제 5연전을 확인합니다. 300턴 경계는 종료 훅 검사로, 실제 엔진의 턴 제한·5:5 단체전은 2턴 제한 검사로 확인했습니다. 실제 300턴 경기 완주, 모든 도구·특성·폼의 조합 및 브라우저 직접 조작은 이번 검증 범위가 아닙니다.

| 상황 | 확정 규칙 |
| --- | --- |
| 실제 무승부·300턴 종료 | 양쪽 주자 탈락, 양 구단 주자 격파 1점씩 |
| 마지막 주자 동시 탈락 | 5:5 무승부, 승점 1씩 |

| 도구·일회성 효과 | 소모·제거·보호 형태의 소모 상태 유지 |

#### 구현 방식

- 경기 준비 화면에 “대회 규정”을 펼쳐 볼 수 있게 합니다. 허용 변신, 턴 제한과 인계 규칙을 짧게 표시합니다.
- 규정은 한 데이터에서 읽고 실제 전투·AI 가상 전투·관전 설명에 함께 사용합니다.

- 서버 시간 초과나 통신 실패를 경기 패배로 처리하지 않습니다.
- 인계가 필요한 도구·일회성 효과·상태 내부값은 HP·PP와 함께 개체 ID 기준으로 저장합니다.
- 규정 변경 전 경기에는 당시 규정 버전을 남깁니다. 이미 완료한 경기의 결과를 새 규정으로 소급 변경하지 않습니다.

2026년 10월 27일 결정한 리그 규칙 v1입니다. 아래는 개발 시 적용할 기준이며, 현재 코드에 모두 구현됐다는 뜻은 아닙니다. 수치 조정은 검증 결과를 근거로 버전을 올려 적용하며, 이미 완료한 경기와 생성된 개체를 소급 변경하지 않습니다.

### 4-1. 승패·무승부·순위

현재 순위 규칙 버전은 `standings-v1-20261027`입니다. 전투 규칙 버전과 분리하여 보관하므로 순위표 개선만으로 확정한 경기 입력·관전 기록을 무효화하지 않습니다.

- 먼저 전체 승점·격파 득실·격파 득점·승리 수가 모두 같은 구단 집단을 만듭니다. 해당 집단 안의 홈·원정 결과만 합산하고, 상대 승점·득실로 일부가 갈려도 남은 구단끼리 다시 계산하지 않습니다.
- 새 시즌 시작 시 구단 ID·시즌·독립 시드로 부별 추첨 순서를 생성하여 저장합니다. 경기·훈련 난수를 소비하지 않으며, 경기 진행이나 새로고침 때 다시 추첨하지 않습니다. 이름이나 ID 알파벳순을 마지막 순위 기준으로 쓰지 않습니다.

- 순위표에서 1~4부 선택, 격파 득점, 동률 집단의 구단명·상대 승점·상대 득실, 공개 추첨 순번을 확인할 수 있습니다. 감독의 구단 평가와 승강 계산도 같은 정렬 결과를 사용합니다.
- 새 시즌 전환 전에 최종 순위·적용 규정·추첨·승강 결과를 시즌별로 보관하고, 순위표에 직전 시즌 기록을 표시합니다. 전 시즌 선택·개별 경기·트레이너/포켓몬 기록을 합친 통합 기록실은 별도 남은 작업입니다.

- 자폭·반동 등으로 엔진이 승리 처리했지만 생존 포켓몬이 없는 주자는, 상대의 다음 주자가 남아 있을 때 전력 소진으로 함께 퇴장합니다. 해당 대결의 엔진 승리는 그대로 기록하고, 전력 소진 퇴장을 포켓몬 개인 격파로 추가하지 않습니다. 상대의 마지막 주자를 이겨 이미 단체전이 끝났다면 승리를 다시 뒤집지 않습니다.

- 한쪽만 주자를 모두 소진하면 반대 구단의 승리입니다. 양쪽이 동시에 다섯 주자를 소진하면 5:5 무승부입니다. 무승부를 포함해 한 단체전은 최대 9번의 주자 대결로 끝납니다.
- 같은 장면 반복이나 회복·교체 횟수만으로 조기 패배를 주지 않습니다. 정상 경기의 무한 진행 방지는 300턴 제한으로 처리합니다.
- 통신 실패·서버 시간 초과·엔진 예외는 미완료입니다. 주차·승패·보상에 반영하지 않고 같은 확정 입력과 시드로 재시도합니다.
- 승점은 승리 3, 무승부 1, 패배 0입니다. 순위는 승점 → 주자 격파 득실 → 주자 격파 득점 → 승리 수 → 동률 구단 간 승점 → 동률 구단 간 격파 득실 순입니다. 끝까지 같으면 시즌 시작 때 공개·저장한 추첨 순번을 사용합니다. 추가 순위 결정전은 만들지 않습니다. 다자 동률의 상대 전적은 해당 동률 집단의 경기만 합산하고 재귀적으로 다시 나누지 않습니다.

이유: 체력이 많은 편성에 유리한 임의 판정승을 피하고, 18라운드 일정과 연승전 형식을 유지합니다.

### 4-2. 다음 상대에게 이어지는 상태

이유: 한 주자가 연승할수록 자원이 줄어드는 구조를 유지하면서, 새로운 전장에 이전 날씨나 설치기가 남는 오류를 막습니다.

### 4-3. 특수 변신과 강화권

구현: 경기 준비에서 주자별 강화 방식·대상 개체·테라 타입을 등록하고 출전 사본과 식별값에 고정합니다. `src/battle/enhancement.js`가 실제 전투와 직렬화한 AI 탐색에 동일한 사용 제한을 설치합니다. 사용 여부는 주자 대결 결과에 저장하고, 승자가 다음 상대를 만날 때 전달합니다. 다음 공식 단체전은 미사용 상태로 시작합니다.

- 사용자 등록의 기본값은 사용 안 함입니다. 상대 AI는 명시적인 등록이 없으면 메가 → Z → 테라 순으로 조건을 만족하는 첫 개체를 사전 등록합니다. 실행 중 대상을 바꾸지 않습니다.
- 메가스톤·화룡점정, Z크리스탈·대응 기술, 다이맥스 금지 종·장비, 고정 테라 타입을 검사합니다. 전체 기술 습득 자격·모든 폼 장비 조합의 심사는 별도 미완료 항목입니다.
- 현재 AI는 등록 개체가 처음 기술을 선택할 때 메가·다이맥스·테라를 사용하고, Z기술은 일반 기술과 함께 평가합니다. 강화권을 나중 대결까지 전략적으로 아끼는 판단은 후속 개선입니다.
- 원본의 실제 발동 로그를 기준으로 사용을 확정합니다. Z파워 발동 후 방어·무효로 실패하면 소비합니다. 기절·수면 등으로 발동 자체에 도달하지 못하면 소비하지 않습니다. 레쿠쟈의 화룡점정 방식도 메가 사용으로 기록합니다.
- 관전에 등록 대상·테라 타입·남은 사용권을 표시하며, 발동 장면을 주요 장면에 포함합니다. 다음 대결에서 메가·테라 및 스텔라 타입별 강화 소모 이력을 유지하고, 다이맥스는 정상 해제한 HP로 인계합니다.


- 메가진화·Z기술·다이맥스·테라스탈은 모두 리그에서 허용하되, 트레이너마다 한 공식 단체전 전체에서 강화권 1회만 사용합니다. 네 종류 중 하나를 선택하며 서로 중복 사용할 수 없습니다.
- 트레이너가 실제로 강화 행동을 시도하기 전까지 강화권은 남습니다. 행동에 도달한 Z기술이 방어·무효 등으로 실패해도 사용한 것으로 기록합니다. Z기술을 쓰기 전에 기절하여 행동 자체를 못 했다면 소비하지 않습니다.
- 준비 화면에서 강화 방식과 대상 포켓몬을 등록합니다. 대회 참가에 필요한 종·도구·폼 등 원본 조건을 충족해야 하며, 실제 사용 시점은 트레이너 AI가 결정합니다.
- 생존한 메가진화·테라스탈 개체는 다음 상대에게도 해당 모습을 유지합니다. 일시적으로 바뀐 타입만으로 전문 타입 보너스를 새로 얻지는 않습니다.
- 다이맥스는 원본의 최대 3턴을 따르며 주자 대결이 먼저 끝나면 즉시 해제합니다. 남은 턴은 다음 대결에 넘기지 않고 강화권도 돌려주지 않습니다. HP는 엔진의 정상 해제 처리를 거친 뒤 10% 회복합니다.
- 변신·배틀 중 조건부 폼 변경·종의 기본 특성으로 발생하는 형태 변화는 강화권과 별개입니다. 단, 강화를 유발하는 메가진화 방식은 도구 사용 여부와 관계없이 강화권에 포함합니다.
- 강화권 사용 상태는 실제 전투·AI 탐색·관전·다음 주자 대결에서 동일하게 사용합니다.

이유: 세대별 특징을 살리면서 한 트레이너가 여러 강화 수단을 연달아 사용해 연승전을 독점하는 상황을 제한합니다.

### 4-4. 전문 타입 편성 보너스

구현: `src/core/team-specialty.js`에서 원래 출전 6마리의 공통 타입과 보정 대상 스탯을 정의합니다. 전투 어댑터는 등록된 종의 Showdown 타입으로 자격을 직접 계산하며, 요청 데이터가 주장하는 보너스 값은 사용하지 않습니다. 상대 분석에도 같은 공통 타입 판정을 표시하지만 기존 출전 순서 추천 점수는 변경하지 않습니다.

- 준비 화면에 적용 기준을 표시하고, 상대 분석의 우리 팀·상대 상세에 공통 타입과 적용 여부를 보여줍니다. 분석 기록은 분석 당시 명단 기준이며, 명단 변경 후 다시 분석할 수 있습니다. 기존 형식의 분석 기록은 재분석 안내로 전환합니다.
- 관전에는 대결마다 양쪽 주자의 전문 타입과 보너스를 표시합니다. 연승 중 기절이나 폼·타입 변경으로 자격을 다시 판정하지 않습니다.
- 종족값·CA·성격으로 새 스탯을 만든 뒤 공격·방어·특공·특방에 `floor(값×105/100)`을 적용합니다. 같은 계산 경로를 초기 주입과 폼 변경에 사용하고, AI 복제에는 개체별 자격 정보를 보존합니다.
- 변신은 상대의 실제 비HP 스탯을 그대로 복사합니다. 변신 상태의 최대 HP 갱신이 복사 스탯에 자기 보너스를 다시 적용하지 않게 처리하며, 교체로 변신이 풀리면 자기 종과 원래 자격으로 재계산합니다.


- 출전 확정 때 등록한 원래 6마리의 타입에 공통 타입이 있으면 전문 편성입니다. 복합 타입도 인정하며, 후보 포켓몬은 판정에서 제외합니다.
- 해당 6마리의 공격·방어·특수공격·특수방어에 각각 5%를 적용합니다. HP·스피드·CA·PA·기술 위력·명중은 바꾸지 않습니다.
- 공통 타입이 둘이어도 한 번만 적용합니다. 기절하거나 일부 개체의 타입이 바뀌어도 해당 단체전의 편성 자격은 유지합니다.
- 능력치 계산 순서는 종족값·CA·성격 → 전문 편성 1.05배 후 내림 → 배틀 중 원본 보정입니다. 폼 변경 시 다시 계산하되 중복 곱하지 않습니다.
- 변신으로 상대 스탯을 복사할 때 이미 적용된 보너스 위에 자기 보너스를 다시 곱하지 않습니다. 실제 전투와 AI 탐색이 같은 복사 결과를 사용해야 합니다.
- 고정 피해 기술에는 별도 5% 피해 보너스를 주지 않습니다.

이유: 공통 약점을 감수하는 편성에 작은 이점을 주되 혼합 타입 편성을 밀어내거나 스피드 순서를 뒤집는 보너스는 피합니다.

### 4-5. 레벨 없는 기술·진화

**기술**

- 기술은 해당 종의 공식 세대별 습득 목록을 합친 범위에서 편성합니다. 레벨별 습득 제한은 사용하지 않습니다. 정식 출시 종·기술만 허용하고 CAP 창작·미출시 데이터는 제외합니다.
- 메가진화·Z기술·다이맥스 전용 기술은 원본의 변환 과정으로만 사용합니다. 일반 기술 슬롯에 직접 등록하지 않습니다.
- 나이트헤드·지구던지기는 50 고정 피해, 사이코웨이브는 25~75 피해를 유지합니다.
- 일격기는 기술의 기본 명중률을 사용하고 레벨 차이 보정·레벨 우열에 따른 사용 제한을 제거합니다. 타입·특성·방어·비레벨 조건은 원본을 유지합니다.
- 셸암즈의 물리·특수 판단은 새 전투 능력치로 계산한 각 경우의 기대 피해를 비교합니다. 상대 HP나 레벨을 임의로 대입하지 않고 동률이면 특수로 처리합니다.
- 그 밖의 레벨 참조는 전수 조사하여 피해·명중·사용 가능 여부에 개별 레벨이 관여하지 않게 수정합니다. 내부 호환 레벨을 성장 수치로 다시 사용하지 않습니다.

**진화**

- 기존 레벨 도달 조건은 현재 형태로 6주 보유하고 유효 육성 활동 4회를 완료하는 조건으로 대체합니다. 주당 최대 1회 집계하며 이미 PA 상한에 도달한 포켓몬도 실제 훈련에 참여하면 집계합니다.
- 다단 진화는 진화할 때 형태별 주차와 육성 횟수를 새로 시작합니다. 훈련 경험을 여러 단계에서 중복 사용하지 않습니다.
- 원본의 성별·성격·보유 기술·지역·시간대·아이템·기술 사용 실적 등 레벨 이외 조건은 함께 충족해야 합니다. 레벨 조건을 대체한 6주·4회는 모든 진화에 추가하는 공통 세금이 아닙니다.
- 친밀도는 0~100, 처음 50입니다. 유효 육성 활동 +2, 실제 경기 출전 +3으로 주당 최대 +5이며, 친밀도 진화 기준은 80입니다. 이적·후보 전환으로 초기화하지 않습니다.
- 교환만 필요한 진화는 트레이너 본인이 신청하는 1주 교류 임무로 대체합니다. 포획자와 소유권은 바뀌지 않으며 필요한 보유 도구는 소모합니다. 특정 종끼리 교환해야 하는 경우도 원본 상대 종 조건을 만족하는 NPC 교류로 처리합니다.
- 도구 진화는 해당 도구를 소모합니다. 분기 진화는 조건이 맞는 경로 중 트레이너의 전술 적합도를 우선하고 동률이면 개체 ID에 따른 고정 선택을 사용합니다.
- 종별 특수 조건은 데이터 표로 관리합니다. 조건이 구현되지 않은 종을 다른 임의 조건으로 진화시키지 않습니다.
- 단장은 진화를 권고하거나 보류할 수 있고, 조건을 충족한 뒤 트레이너가 주간 육성 과정에서 실행합니다. 진화 도중 자동으로 주차를 진행하지 않습니다.
- 개체 ID·포획자·6개 CA/PA·경력은 그대로 유지합니다. 바뀐 종족값·타입·특성에 맞춰 전투 데이터를 갱신하며, 기술은 새 종에서도 합법적인 구성으로 확인합니다. 진화로 은퇴 시점이나 강화권을 초기화하지 않습니다.

이유: 포켓몬 레벨을 되살리지 않고 육성과 종별 특징으로 진화하며, 낮은 PA 때문에 영구적으로 진화하지 못하는 경우를 막습니다.

### 4-6. 파견·출전·보유 인원

- 지역 탐색은 1주입니다. N주에 출발하면 N+1주 시작 시 결과를 먼저 정산합니다. 실제 시간 대기는 없습니다.
- 파견 중인 주에는 해당 트레이너의 정규 훈련·기술 연구·공식 경기 출전을 허용하지 않습니다. 경기 주차에 등록할 주전은 파견할 수 없고 후보를 활용합니다. 다음 주 경기라면 그 주 시작 시 귀환한 뒤 출전할 수 있습니다.
- 한 구단은 주전 5명·후보 최대 5명·아카데미 최대 10명을 보유합니다. 아카데미에서 승격한 뒤 탐색·공식 경기 활동을 시작합니다.
- 아카데미가 10명으로 가득 찼으면 신인 추가 생성을 중단하고 정리 안내를 표시합니다. 기존 신인을 자동 삭제하지 않습니다.
- 트레이너는 출전 6마리를 포함하여 현역 포켓몬 최대 12마리를 보유합니다. 포켓몬을 다른 트레이너에게 넘기는 기능은 제공하지 않습니다.
- 포획 후보는 트레이너당 1마리만 등록 대기할 수 있습니다. 대기 중에는 재파견하지 못합니다. 12마리 상한에 도달하면 보유 개체 방출 또는 후보 포기 중 선택하며 자동 방출은 하지 않습니다.
- 은퇴·계약 종료 등으로 출전 5명·각 6마리를 갖추지 못하면 빈자리를 채우도록 안내합니다. 경기 시점까지 충원하지 못한 구단은 0:5 몰수패입니다. 상대에게도 출전 개인 기록·올킬 기록은 주지 않습니다.
- 양쪽 모두 미충원이라면 0:0 양패로 별도 기록하고 승점·경기 보상을 모두 주지 않습니다. 행정 양패는 일반 무승부와 구분하고, 통계 검증에서도 일반 경기의 승패 합계와 별도로 셉니다.
- 기존 저장이 상한을 초과하면 즉시 삭제하지 않고 신규 영입·포획 등록을 막습니다. 선수를 내보내 상한을 충족한 뒤 추가할 수 있습니다.

이유: 파견에 후보 활용이라는 선택을 주면서, 귀환 순서나 자동 방출 때문에 선수가 사라지는 상황을 방지합니다.

### 4-7. 탐색·개체 감별과 초기 CA/PA

- 트레이너의 포획 분야 능력은 탐색·포획과 개체 감별 두 개로 고정하고 각각 1~20을 사용합니다. 발견과 포획 성공은 모두 탐색·포획 능력을 사용합니다. 개체 감별은 발견된 같은 종의 CA/PA 분포에만 영향을 줍니다.
- 원래 지역·서식지·시간대에 나오지 않는 종을 높은 능력 때문에 추가하지 않습니다.
- 종별 기본 출현 가중치는 기존 표를 유지합니다. 탐색·포획 s에 대해 각 종의 종족값 합계를 B라 할 때 `기본 가중치 × (1 + ((s-1)/19) × clamp((B-300)/300, 0, 1))`로 보정한 뒤 정규화합니다. 높은 능력은 높은 종족값 종의 상대적 조우 가능성을 높이되 확정 포획을 만들지 않습니다.
- 발견·포획의 기존 지역·희귀도 보정과 확률 상한은 유지하고, UI 표와 실제 추첨은 같은 함수를 사용합니다. 별도 captureSkill은 탐색·포획으로 통합합니다. 이전 저장은 기존 skill을 탐색·포획으로 사용하고 개체 감별은 기존 captureSkill을 초기값으로 보존한 뒤 두 값의 역할을 바꿉니다.
- 신규 야생 포켓몬의 각 능력치는 별도로 추첨합니다. 개체 감별 t, `a=(t-1)/19`일 때 PA 구간은 다음과 같습니다.

| PA 구간 | 선택 확률 |
| --- | --- |
| 50~110 정수 균등 | (70−20a)% |
| 111~160 정수 균등 | (25+10a)% |
| 161~200 정수 균등 | (5+10a)% |

- 각 능력치 CA는 해당 PA에 `0.40~0.70 균등 난수 + 0.10a`를 곱한 뒤 내림하며 최소 1입니다. 각 스탯에 독립 추첨하고 항상 CA≤PA를 보장합니다. 희귀종이라는 이유만으로 개체 CA/PA까지 추가 보너스를 주지 않습니다.
- 새 게임의 주전 초기 CA 중심값은 1부 100·2부 85·3부 70·4부 55입니다. 각 능력치에 −15~+15 정수 편차를 주고 PA는 CA에 20~60을 더해 200을 상한으로 합니다. 후보는 해당 부 중심값−10, 아카데미는 CA 중심값 40으로 생성합니다. 시즌 수에 따라 생성 기준이 상승하지 않습니다.
- 기존 개체는 재추첨하지 않습니다. 초기 구단의 부별 전력과 야생 개체의 분포는 다른 생성 목적이며, 승강·이적 후 소속 부에 맞춰 CA/PA를 강제로 바꾸지 않습니다.
- 실제 전투 공식은 현재 구현을 v1로 유지합니다. HP는 `floor(0.80×종족 HP + 0.95×HP CA + 45)`, 다른 스탯은 `floor((0.80×종족값 + 0.70×해당 CA + 10)×성격 배율)`입니다. 일반 피해 계수 28, 껍질몬 HP 1을 유지합니다. PA는 성장 상한으로만 사용하고 별도 IV·EV 성장치를 추가하지 않습니다.
- 밸런스 검증은 같은 CA에서 종별 강점이 유지되는지, CA 증가가 해당 스탯에만 반영되는지, 새 시즌을 반복해도 초기 분포가 부풀지 않는지 확인합니다. 승률 목표를 맞추려고 경기 중 상대 능력치를 보정하지 않습니다.

이유: 종의 희귀성과 개체의 성장성을 분리하고, 상위 부와 장기 육성의 차이를 시즌 인플레이션 없이 만듭니다.

### 4-8. 포켓몬·트레이너 은퇴

- 포켓몬의 현역 기간은 개체 생성 시 ID와 생성 시드로 정한 8~12시즌입니다. 모든 종에 같은 범위를 적용합니다. 전설·희귀종이라고 면제하지 않습니다.
- 은퇴는 시즌 종료 때만 처리하며 2시즌 전에 예정 시즌을 공개합니다. 첫 보유 시즌을 활동 1시즌으로 세고 후보·보관·이적 중에도 경력이 흐릅니다. 신규 생성 아카데미 개체도 동일합니다.
- 기존 저장은 활동 시즌을 유지하고, 이미 은퇴 예고가 있으면 그 일정을 보존합니다. 예고가 없으면 변환 시점으로부터 최소 2시즌 뒤로 잡아 예고 없는 은퇴를 막습니다.
- 은퇴 자체로 CA/PA를 미리 깎지 않습니다. 별도의 노화·부상 제도는 v1에 추가하지 않습니다.
- 트레이너는 기존의 희귀 은퇴 방식에 맞춰 시즌 종료 시 현역당 1.4%로 은퇴를 예고합니다. 예고 다음 시즌 종료 때 65%로 은퇴, 35%로 보류하며 다시 현역으로 남습니다. 판정은 시즌·트레이너 ID 기준으로 저장하여 재접속으로 바뀌지 않습니다.
- 트레이너가 은퇴하면 본인이 포획한 포켓몬 전체도 공식 출전에서 제외하고 은퇴 기록으로 보존합니다. 다른 트레이너에게 재배정하지 않습니다. 트레이너를 따라 떠나는 전속 선수단이라는 뜻이며 개체 정보를 삭제하지 않습니다.
- 계약 종료·이적은 은퇴가 아닙니다. 트레이너와 현역 보유 포켓몬 전체가 함께 이동합니다. 미정산 파견과 포획 후보도 해당 트레이너에게 귀속되며, 확정 경기 중 이동은 금지합니다.
- 포켓몬 은퇴·트레이너 은퇴 직후 무료 대체 선수를 즉시 생성하지 않습니다. 아카데미 승격·후보 활용·이적·탐색으로 충원합니다. 예정 공석은 알림함에서 미리 보여줍니다.

이유: 종별 수명 논쟁 대신 예측 가능한 활동 경력을 사용하고, 소유권을 깨뜨리는 은퇴 개체 재활용과 무료 전력 보충을 막습니다.

### 4-9. 재정 적자와 시즌 평가

**재정**

- 수입·현금·미지급금을 분리합니다. 자동 필수 지출을 낼 수 없으면 현금은 0까지만 쓰고 나머지는 미지급금으로 기록합니다.
- 미지급금이 있는 동안 유료 영입·시설 확장·유료 탐색 등 선택 지출을 막습니다. 비용 증가가 없는 후보 배치·아카데미 승격·선수 매각과 일정 진행은 허용합니다.
- 이후 들어오는 수입의 50%를 미지급금 상환에 우선 사용합니다. 잔액보다 많이 상환하지 않으며, 남은 수입은 현금이 됩니다. 일반 필수 지출은 계속 정산합니다. 별도 대출·복리 이자·자동 구제금은 만들지 않습니다.
- 승점 삭감·강제 매각·단장 해임·자동 게임 종료는 적용하지 않습니다. 재정 문제로 선택지가 제한되는 방식으로 운영합니다.
- 모든 거래·상환은 사건 ID로 한 번만 처리하고, 거래 실패 시 돈과 선수단을 함께 원상복구합니다.

**계약·지급 기준**

- 연봉은 원 단위 시즌 총액입니다. 1~30주차 누적 지급액을 기준으로 분할하고, 30주차에는 시즌 총액과 정확히 일치시킵니다. 소속 기간의 급여만 부담합니다. 기존 저장에는 도입 이전 주차를 소급 청구하지 않습니다.
- 주간 급여 정산 전의 입단·이적·재계약·종료는 해당 주차부터 적용합니다. 해당 주차 정산 이후 처리된 변경은 다음 주차부터 적용해 같은 급여 기간을 두 구단에 중복 청구하지 않습니다.
- 입단 계약은 이번 시즌을 포함해 1~3시즌, 기본 2시즌입니다. 연봉은 기존 요구액의 100%·110%·125% 중 선택하고, 계약금은 합의한 시즌 연봉의 10%입니다. 시즌 중 입단의 총 지급액은 소속 주차만 계산하므로 화면의 연봉×시즌 수는 상한으로 표시합니다.
- 연봉 인상 제안은 기존 트레이너 수락 확률에 인상 비율의 절반을 더합니다. 예를 들어 10% 인상은 +5%p이며, 기존 확률 상한은 유지합니다. 구단의 이적료 수락 확률과 구분합니다.
- 재계약은 이번 주부터 적용할 연봉과 기존 만료 뒤 1~3시즌의 연장을 선택합니다. 계약금은 새 시즌 연봉의 10%이며, 같은 주차 재계약은 한 번만 처리합니다. 자유계약 영입은 기존 요구 연봉·2시즌·계약금 10%를 기본으로 합니다.
- 아카데미의 최초 계약은 일반 요구 연봉의 25%인 육성 수당입니다. 승격만으로 수당을 인상하지 않고 같은 계약을 유지합니다. 이후 재계약에서 조건을 바꿀 수 있습니다.
- 계약 만료 4주 전부터 감독에게 결정을 요청합니다. 만료 후 퇴단을 선택해도 남은 계약 기간의 급여는 지급합니다. 실제 만료는 마지막 주차 지급 이후 적용하며, 트레이너와 보유 포켓몬·경력·탐색 정보는 함께 자유계약 시장으로 이동합니다. 은퇴와 구분합니다.
- 주차·구단·트레이너·계약 식별값을 급여 내역에 남깁니다. 경기 수입·지원금·탐색·조사·재계약도 사건 ID로 기록합니다. 시즌 재정 기록은 30주차 지급 후 확정하며, 현재 계약의 잔여 급여와 미지급금만 확정 부담으로 전망에 반영합니다. 아직 승인하지 않은 시설·훈련·영입과 향후 경기 보상·매각 수입은 포함하지 않습니다.

이유: 기존 연봉과 훈련비를 임의로 높이지 않고 실제 지급·소속 기간·신규 계약의 부담부터 연결합니다. 아카데미 승격에는 현금 없이도 선수단을 유지할 선택지를 남깁니다.

**평가**

- 시즌 시작 때 등록한 선수단의 부 내 예상 전력 순위로 목표를 고정합니다. 예상 상위 3구단은 3위 이내, 중위 4~7구단은 6위 이내, 하위 3구단은 8위 이내가 목표입니다. 첫 비교에는 보유 정보가 같은 전력 평가 함수를 사용합니다.
- 종합 평가는 성적 60%·육성 25%·재정 15%입니다. 성적 점수는 `clamp(60 + 15×(목표 순위−실제 순위), 0, 100)`입니다.
- 육성 목표는 소속 기간 30주당 현역 보유 포켓몬 1마리의 총 CA +2입니다. 시즌 시작 또는 영입·포획 등록 때 남은 PA 여유의 합과 2 중 작은 값을 개인 목표로 저장하고 실제 소속 주차/30을 곱합니다. 목표 분모를 매각으로 삭제하지 않으며, PA 상한 개체의 목표는 0입니다.
- 육성 점수는 전체 목표 대비 소속 중 얻은 실제 CA 증가 비율로 계산해 100점을 상한으로 합니다. 목표의 소속 주차 비율은 1을 상한으로 합니다. 각 개체의 인정 성장도 개인 목표를 상한으로 하여 에이스 1마리만 과잉 훈련하는 편법을 막습니다. 전체 목표가 0이면 100점입니다. 진화·이적·저장 변환으로 바뀐 표시값은 훈련 성장으로 세지 않습니다.
- 재정 점수는 시즌 내내 미지급금이 없었으면 100점, 도중 연체가 있었지만 종료 전에 모두 갚았으면 50점, 종료 시 미지급금이 남으면 0점입니다.
- 결산은 항목별 목표·실적·점수를 보여주고 시즌별로 보존합니다. v1은 보고서만 제공하며 평가 점수로 돈·CA·승점을 지급하지 않습니다. 목표와 점수는 정산 후 바꾸지 않습니다.

이유: 파산 때문에 진행이 막히는 상황을 피하면서 지출 제약으로 책임을 주고, 평가 보상으로 자산과 능력치가 다시 증식하는 구조를 만들지 않습니다.
