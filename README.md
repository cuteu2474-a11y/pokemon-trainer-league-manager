# Pokémon Trainer League Manager

포켓몬 트레이너 5명으로 구성된 구단을 운영하는 HTML 기반 싱글플레이 경영 시뮬레이션입니다. 플레이어는 구단 단장이 되어 트레이너와 포켓몬을 영입·육성하고, 자동 전투 전술과 출전 순서를 정해 4부에서 1부 우승에 도전합니다.

> 현재 상태: **구단 운영 웹 시제품 + 별도 Showdown 전투/리그 엔진**. 최신 운영 화면과 확정 로고를 main에 통합했습니다. 화면의 경기 진행은 간이 시뮬레이션이며, 실제 전투 엔진을 화면에 연결하는 작업은 다음 단계입니다.

## 핵심 규칙

- 리그는 1~4부 승강제. 구단끼리 직접 홈·원정 대결을 진행합니다.
- 한 구단은 트레이너 **5명**을 출전시키며, 각 트레이너는 포켓몬 **6마리**를 사용합니다.
- KOF식 연승전: 트레이너가 지면 탈락하고 다음 트레이너가 등장하며, 이기면 계속 출전합니다.
- 상대 트레이너를 격파할 때 생존 포켓몬은 **최대 HP의 10% 회복**. 기절한 포켓몬은 부활하지 않습니다.
- 모든 포켓몬 타입을 자유롭게 편성할 수 있습니다. 한 트레이너의 출전 6마리가 공통 타입을 가지면 별도의 능력치 보너스를 받습니다.
- 기술 및 포켓몬 교체는 트레이너 AI가 판단합니다. 단장은 선수단 편성, 출전 순서, 전술 방침을 관리합니다.
- 포켓몬은 트레이너를 특정 지역에 파견하는 **지역 탐색 임무**로 포획합니다. `탐색·포획`은 다양한 종과 높은 종족값의 종을 발견할 가능성, `개체 감별`은 같은 종 내에서 높은 현재 능력(CA)·잠재 능력(PA)을 지닌 개체를 발견할 가능성에 영향을 줍니다. **자신이 포획한 포켓몬은 해당 트레이너만 사용할 수 있습니다.**
- 포켓몬의 전통적인 IV(0~31) 대신 FM식 **현재 능력(CA)·잠재 능력(PA)** 성장 체계를 적용합니다. CA는 성장할 수 있지만 PA는 개체별 성장 한계입니다.
- 트레이너가 다른 구단으로 이적하거나 계약 만료로 구단을 떠나면 **본인이 포획한 포켓몬 전부를 데려갑니다.** 트레이너 은퇴 시 처리는 추후 결정합니다.
- 트레이너마다 FM식 **선호 플레이(선플)**를 부여해 자동 배틀·탐사·육성의 행동 성향을 차별화합니다. 선플 목록과 세부 규칙은 설계 중입니다.
- 포켓몬 은퇴와 세대교체가 장기 운영의 핵심입니다. 시즌이 흐른다는 이유만으로 각 부의 기본 전력 수준이 자동 상승하지 않습니다.

자세한 확정 사항과 미확정 사항은 [게임 기획서](docs/GAME_DESIGN.md)를 참고하세요.
트레이너 세부 능력치와 선플 제안은 [트레이너 시스템 설계](docs/TRAINER_SYSTEM.md)를 참고하세요.

## 운영 원칙

- `main` 브랜치 하나를 기본으로 사용합니다.
- 자동 실행 워크플로는 필요해질 때만 추가합니다.
- 기능과 규칙 검증을 그래픽·연출보다 우선합니다.
- 이 프로젝트는 비공식 포켓몬 팬게임 기획이며, 공식 권리자와 관계가 없습니다. 공개 배포 시 명칭·캐릭터·이미지 등의 권리 문제를 검토해야 합니다.

## 실행 및 검증

Node.js 20 이상에서 실행합니다. 웹 화면은 외부 이미지 12개를 사용하므로 `index.html`만 복사하지 말고 저장소 전체를 사용하세요.

```bash
npm ci
npm run check:web
npm test
npm run dev
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. `npm run dev`는 로컬 확인용 정적 서버입니다. Showdown API 서버를 시작하지 않습니다.

- `index.html`, `assets/ui/`: 현재 운영 화면과 로고.
- `src/battle/`: 실제 6대6 전투, AI, 5인 연승전.
- `src/league/`: 선수단 생성, 일정, 순위 및 승강 처리.
- `tests/`: 엔진 검증. 전체 시즌의 빠른 시뮬레이션과 일부 실제 Showdown 경기를 구분해 검증합니다.
- [통합 기준 버전 및 남은 연결 작업](docs/ui-integration-status.md)
